# docs/ 维护规范

- 本目录是跨工具（Kilo Code、Codex）与作者共享的科研记录，随仓库通过 GitHub 同步。
- 状态语义（在 STATUS.md 与日志中统一使用）：【已完成】工作做完且有产出物；【已验证】有运行结果或数据支撑的结论；【进行中】正在做；【假设】未验证的想法；【计划】下一步打算。不得把假设或计划写成已验证。
- 日志按日期命名（YYYY-MM-DD.md）；同一天多次工作采用追加方式，不删改既有历史条目；如需更正，追加「更正」小节并注明原因。
- 日志正文标题与叙述不写「上午/下午/傍晚」等时段词（文件名日期已定位到天）；引用命令输出或系统日志中的原始时间戳（如 journalctl 的 17:31:43）作为证据时不受此限。
- 记录运行命令时保留原文（含参数与路径）；记录数值结果时注明来源（命令输出、日志文件路径或论文表格编号）。
- 本目录文件由任务结束时的更新流程维护（见根目录 AGENTS.md「任务结束时」），日常不必逐字同步。
- 周报放在 docs/reports/，命名 `YYYY-MM-DD.md`（用撰写当天的实际日期；间隔不严格要求 7 天，实事求是），每周最后一个工作日完成；内容结构固定：本周概述 / 主要进展 / 问题与解决 / 数据与结论 / 风险与限制 / 下周计划。周报只汇总事实，素材取自当周 docs/logs/ 与 STATUS.md，不引入未经记录的新结论；正文同样不写时段词。
