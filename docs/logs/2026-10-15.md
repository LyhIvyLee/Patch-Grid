### S3 执行记录（命令原文 + 结果）

1. 冒烟测试：`python train.py --dataset_path data/train/00000006_0 --exp_name smoke_00000006_0 --pretrained _results/shape_space/decoder_1.pth --fix_decoder --use_shape_space --epochs 2` → 首跑因 setuptools 80.9 的 distutils 兼容问题失败（`distutils.version.LooseVersion` AttributeError），按官方 yaml 钉子降级 `setuptools==58.2.0` 后通过：采样/前向/反向/存 ckpt 全 OK，显存 15MiB，采样缓存落 data/samples/。
2. 正式拟合（example.sh 官方命令）：`--exp_name 00000006_0_ss`（默认 300 epochs）→ 301 iters / **13.4s**；损失 patch 57.9→0.242（milestone 270/285 衰减后进一步下降）；`_results/models/00000006_0_ss.pth`。
3. 提取（两次资源适配，均官方参数旋钮、零代码修改）：
   - 默认参数 → GPU OOM（80 万点批次的 [N,8,256] gather + 反向图 > 5.64GiB）；
   - `--extract_batch_size 200000` → 仍在 grad_compute OOM（该批次结构仍需 ~4GB）；
   - `--extract_batch_size 50000` + `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:128` → GPU 峰值 2.75GB 稳定，但 **2048 分辨率的 CPU 拼接阶段导致系统 RAM OOM：VSCode 被 OOM killer 杀死（17:31 会话闪退原因）**，3127 分块/734MB 载入膨胀所致；
   - 最终：`--extract_resolution 1024 --extract_batch_size 50000` → **成功**（约 2 分钟），`_results/mesh/00000006_0_ss_composed_all.obj`（142MB / 1,849,749 verts / 3,466,961 faces）；2048 失败产物保留于 `_results/mesh/00000006_0_ss_oom2048/`。
   - 几何验证：重建包围盒 [-0.694,-0.801,-0.231]~[0.694,0.801,0.231] vs GT 偏差 ≤0.001；GT watertight、RECON 非 watertight（patch 边界正常现象）。
4. 可视化：`_results/mesh/compare_00000006_0.png`（GT vs 重建，6 万面简化后 matplotlib 渲染）。
5. mesh_metrics：首跑缺 `rtree`（官方 yaml 有 0.9.7，漏装）→ `pip install rtree==0.9.7` 后成功。
